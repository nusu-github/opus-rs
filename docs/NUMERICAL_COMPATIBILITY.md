# Numerical compatibility

The numerical reference is Opus commit
`503d81b138d76621aae4b12786e90de48aa8db3a`. The Rust library implements the
portable scalar algorithms. Architecture-specific assembly and SIMD kernels
are replaced with safe scalar Rust; their independent arithmetic profiles are
not the numerical reference.

The C oracle uses C99, `-O2`, `-ffp-contract=off`, `-fno-fast-math`, and
`-fno-tree-vectorize`, with runtime SIMD dispatch disabled. Float profiles use
`HAVE_LRINTF`, the default rounding mode, and no `FLOAT_APPROX`. Fixed profiles
select `FIXED_POINT`; 24-bit profiles additionally select `ENABLE_RES24`.
PFA and QEXT are separate profiles because they change transform arithmetic.
See [the oracle instructions](../tools/reference/README.md) for reproducible
commands and independent fixture provenance.

Compatibility checks require equal packet bytes, integer PCM samples,
IEEE-754 float bits, sample counts, and entropy final ranges. Successful round
trips and audio-quality scores are insufficient. Each decoder comparison uses
packets generated by the independent C encoder. Fixtures are C outputs, not
Rust-generated expected results.

## Feature matrix

| Cargo features | C configuration and scope |
| --- | --- |
| Default | Scalar float SILK, CELT, and hybrid; 8, 12, 16, 24, and 48 kHz |
| `fixed_point` | Scalar fixed point with 16-bit internal PCM |
| `enable_res24` | Fixed point with 24-bit internal PCM; implies `fixed_point` |
| `pfa` | Prime-factor FFT, including float and both fixed profiles |
| `custom_modes` | Opus Custom, owned dynamic modes, and noncanonical transforms |
| `enable_qext` | QEXT payloads, additional bands, 96 kHz, and Q31 fixed coefficients |
| `osce` | LACE, NoLACE, and BBWENet with owned model blobs |
| `dred` | DRED analysis, packet generation, parsing, and neural processing |
| `deep_plc` | Neural packet loss concealment; implies `dred` |
| `deep_plc_weights` | Bundled verified deep-PLC parameters; implies `deep_plc` |
| `dnn_debug_float` | Diagnostic floating-point neural weight profile |

Float/fixed/24-bit, scalar/PFA, and standard/custom/QEXT profiles have distinct
fixtures. Fixed point cannot be combined with OSCE, DRED, or deep PLC: the
pinned C configuration rejects these combinations, and Rust reports a compile
error. Optional model-fetch features affect build-time parameter acquisition;
they do not introduce network access or C dependencies into the codec.

Ordinary Cargo tests consume committed fixtures without needing a C compiler.
Explicitly ignored oracle tests require independently built C executables and
are run by the reference CI jobs. Test optimization retains debug and overflow
assertions while making exhaustive codec tests practical.

Rust 1.88.0 has also been checked directly for the default library, the combined
24-bit/Custom/PFA/QEXT library, and the combined float neural/Custom/PFA/QEXT
library. CI retains the default and combined fixed minimum-version checks.

## Models and WebAssembly

The pinned model archive is
`opus_data-a5177ec6fb7d15058e99e57029746100121f68e4890b1467d4094aa336b6013e.tar.gz`.
Its filename records the required SHA-256 digest. The older donor model has a
different network and DRED packet version and is not a compatibility reference.
Standard neural builds select C's int8 weights (`DISABLE_DEBUG_FLOAT`);
`dnn_debug_float` selects the separately verified diagnostic float profile.
Both use float codec arithmetic. Model arrays are converted to Rust data at
build time. Runtime model blobs are copied into owned storage and do not leak
or retain caller buffers.

The library and its software math implementation use `no_std` with `alloc` and
enforce `#![forbid(unsafe_code)]`. Cargo does not compile or link the C codec.
The `wasm32-unknown-unknown` build checks the host-independent library; WASI is
used only by the process test adapter. Native/WASI comparisons check the same
packet, PCM-bit, and range outputs. Nine codec profiles cover 3,408 native/WASI
comparisons. The two neural profiles add 2,636 exact comparisons, including
96 kHz QEXT, and eight browser-target builds. See [Wasm verification](WASM.md).
The final fixed stereo-to-mono regression also checks 40 independent C cases
under WASI across eight arithmetic/transform/extension profiles.

## Defined input boundaries

Rust does not reproduce C out-of-bounds accesses or allocation cleanup bugs.
Custom modes whose prediction history is too short are rejected when creating
a decoder; unsupported FFT factors return an error. The canonical 96 kHz mode
has doubled history and supports normal decoding and PLC. See
[Opus Custom](CUSTOM_MODES.md) for the precise construction rules and C fixture
boundaries.

The crate's Rust API is intentionally independent of the C ABI. Floating-point
compatibility is tied to the documented arithmetic profile rather than a
particular CPU's optional accelerated kernels.
